## 1. The Right Fact, the Wrong Decision: SciValidityBench for Scientific Agent Memory

[原始来源](https://arxiv.org/abs/2610.34767)

首发：2026-10-26 · 版本：v1

这篇关注一种比“忘记结果”更隐蔽的错误：代理准确记住了结果，却不知道它是否有资格支持当前结论。作者用同一个 p=0.03 说明区别：预先规定指标和停止规则后得到它，与查看二十个指标后挑出它，科学含义不同。前者可作为确认性证据，后者仍属探索。信息分散在计划、访问记录、结果和停止时机中，只把结果检索回来不能解决问题。

SciValidityBench 用程序生成实验历史，定义可选动作和判定正确动作的规则。系统先给每条计划、运行、观测和访问记录稳定编号，再把跨记录关系整理成明确状态，例如结果是否先于计划锁定被访问、测量之间是否可比、空值为何出现。派生状态保留来源，但不增加新观测。最后模型根据历史或整理后的状态选择动作，由程序判分；这是合成历史上的决策测试，没有操作科学软件或采集实物测量。

主实验把64种任务各生成十个未见种子，交给四类开源模型，比较完整事件、BM25检索、普通事件图，以及内容相同的平铺／带类型科学状态。原始决策共12,800次，另有5,120次反事实决策；主指标先在每种任务内平均，再让64种任务等权。显式状态相对普通事件图提高9.2—18.8个百分点，四组95%区间均高于零。更有说服力的是，作者只改一个决定性条件，测试答案是否随之改变，又把损坏状态原位修复，与修改无关位置比较。结果支持“暴露支配决策的关系”有用，而不是简单说明图结构或更多检索有用；较弱模型的反事实一致性仍差，各机制也并非普遍受益。

**作者证据：** 64任务×10种子×4模型×5表示=12800原决策，另5120反事实；相对事件图提升9.2–18.8个百分点，95%区间>0

**限制：** 确定性状态编译依赖预置规则；未验证从任意截图/仪器日志提取；平铺状态亦可有效

**先读：** §3.3、§4.3–4.4。

## 2. OS-Wizard: Scaling Computer-Using Agents to Specialized Software via Knowledge-Guided Exploration

[原始来源](https://arxiv.org/abs/2610.33907)

首发：2026-10-24 · 版本：v1

专业软件的问题不只是按钮难找。通用代理往往不知道领域操作的前提，盲目探索又很难积累可训练的成功轨迹。OS-Wizard 因而首先是一套自动收集轨迹的方法：用软件教程指导探索，把鼠标键盘动作与软件原生命令一起开放，并保存有价值的中间桌面状态，之后可以回到同一位置尝试其他路径。

具体过程是先从截图、可访问性信息和历史动作提出分支，选出浅层、变化明显或已有成功记录的关键状态，保存虚拟机快照。系统为状态检索相关教程，再生成任务并继续操作；分支越深，探索宽度越小，后段转成连续执行。恢复时从最近快照重放少量动作，并检查画面一致性。GUI动作通过执行与模型验证筛选，原生命令至少须无执行错误，有任务时再判完成。人提供的软件教程、基准和接口条件仍构成知识基础，训练轨迹的生成与多数完成判断由模型承担。

在 ScienceBoard 中，系统可操作Celestia、GRASS GIS、KAlgebra、Lean／TeXstudio等专业应用；除缺少相应编程控制的Celestia外，采用混合GUI与代码动作。命令抽象了本来可以通过界面输入的操作，不能把它写成纯截图CU的成绩。收集的10,919条轨迹包含54,938个状态动作样本，训练后的Qwen3.5-27B成功率从5.9%升至64.1%±0.7%，后者是三轮均值及标准差，作者重跑结果统一上限50步。表中59.8%的人类成绩引自原论文，不能直接当作同条件的人机竞赛。相同两万训练样本预算下，混合数据为55.0%，无代码轨迹训练为26.6%；这支持代码监督的重要性，但也改变了训练轨迹分布，不能单独归因为测试接口。

它使“科学软件CU还缺专业操作能力”这一宽泛动机更难独立成立。值得带走的是教程驱动的知识接入、失败恢复与混合动作选择；需要付出的则是软件专用命令、教程、验证器和训练数据工程。这里的Celestia是计算机天文软件，虚拟机快照也能撤回软件状态，不能据此推到真实望远镜观测的撤回或物理反馈连续性。通用接口与专用能力的边界，必须按实际开放的操作来比较。

**作者证据：** 10919轨迹54938状态动作；Qwen3.5-27B ScienceBoard 5.9→64.1±0.7%，三轮/50步；2万样本混合55.0 vs无代码26.6

**限制：** 混合动作非纯GUI；训练分布混杂；人类59.8为引用非同条件重跑；软件快照不可推物理撤回

**先读：** §3.3、表1、图4(b)。

## 3. Matched Capabilities, Different Behaviors: A Controlled Study of MCP and CLI Interfaces for Language Agents

[原始来源](https://arxiv.org/abs/2610.34298)

首发：2026-10-25 · 版本：v1

比较MCP和命令行时，常常一边开放细粒度工具，另一边允许任意脚本，胜负实际包含能力差异。这篇用MICA先建立共同的操作契约：同一操作和相同类型参数分别表达成具名工具调用、命令与选项，解码以后进入同一验证和执行程序。模型、初始状态、可见信息、生成设置与预算保持一致，因此更能把差异归到接口呈现及其反馈。

实验涉及六个模型，分别运行134个ALFWorld家庭任务、100个WebShop购物任务、100个ScienceWorld科学模拟任务。ScienceWorld提供的是软件环境反馈，不是远程实验室。作者先在相同状态与历史下变换能力说明、动作表达和反馈格式，观察模型是否改变语义选择；再比较整条自然轨迹，定位首次真正不同的决策。2,004对MCP／CLI任务轨迹中，1,889对出现结构性分歧，占94.3%；它表示接口经常改变行为，不表示94.3%的任务失败，也不证明某接口普遍更优。

实际方向确会反转。Qwen3-14B在ALFWorld中，MCP得分20.1、CLI为56.7；同一模型在WebShop中却是64.4对59.5。前者是任务成功表现，后者采用环境原生奖励，不能把两种分数都称作科学验收成功率。调用开销也随环境变化。由于早期动作一旦不同，后续状态和历史便不同，作者把同状态局部检验与分歧后的传播分开，避免把后半段所有差异都视作独立的接口效应。

由此提出的DART先固定已经验证过的语义决定；若只是参数或命令表达失败，就修复表达，不重新选择任务动作。它在Gemini-2.5-Flash的三环境、两接口共六个设置中均提高得分，最大九个百分点；MCP每任务计费token最多减少27.1k，但CLI的开销并非都下降。这里的收益来自额外控制流程，且仍受共同调用预算限制，不能外推为MCP天然节省成本。

**作者证据：** 6模型×334任务=2004对轨迹，1889对结构分歧94.3%非失败率；Qwen14B ALF MCP20.1/CLI56.7，WebShop64.4/59.5；DART至多+9pp

**限制：** 不含截图GUI；不同环境得分含义不同；DART收益包含控制流程；CLI开销不总下降

**先读：** §4、表1、附录B.2。

## 4. MatOS: An Agent Operating System for Materials Research

[原始来源](https://arxiv.org/abs/2610.34203)

首发：2026-10-25 · 版本：v1

材料研究常跨越数据库、文献和多个模拟程序，任务可能运行数天。仅有聊天计划很难保证中断恢复后仍沿用正确结构、参数和参考能量。MatOS把研究能力保存为有编号、有依赖关系的资产，并将当前研究展开成显式执行图：节点写明输入、输出、完成条件以及所调用的方法，结果与产生它的节点和尝试绑定，之后改计划也保留证据来源。

代理承担分解问题、选择方法和解释异常，运行时负责计算提交、记录和恢复；需要研究者判断时可以停在人类节点。新结果返回后，代理或研究者可提议增加验证步骤、修改后续依赖，但要通过结构、权限与可编译检查才生效。文中也设计了根据执行记录和用户反馈修订知识、工具、技能的流程，须经过结构检查和模型语义审查。不过这与基准分数必须分开：全部基准评测冻结资产库，关闭自演化，因此不能用这些结果证明在线自我改进。

ResearchClawBench使用12项端到端任务，以官方量规评估。相同GPT-5.4模型下，MatOS总体分19.46，比最好基线MIRA高11.15%，这是相对提升而非11.15个百分点。更窄的工具任务差距其实很小：MatTools中完成49题里的48题，Codex CLI为47题；SciAgentGym中完成42例里的25例，两种编码代理均为24例。前者用单元测试，后者由六位GPT-5.5评判器各审七例并按严格完整正确口径计数。作者给出的差异包括保持对称等价位点分组、避免把两组位移对应的斜率交换，说明改善可能来自科学对象在软件表示间的一致性，不能把一题差距写成普遍大幅领先。

案例还把约三千万结构筛至97种固态电解质候选，并使用势函数、DFT等计算分析。这里报告的是计算候选和模拟证据；架构中的仪器Backend节点只是可承载的接口类型，所核案例没有据此证明远程新合成或新表征测量自动闭环。许多计算和外部任务由专用程序与工作流接口执行，也不是统一截图GUI。

**作者证据：** ResearchClawBench12任务GPT5.4得分19.46，相对MIRA+11.15%；MatTools48/49 vs47/49；SciAgentGym25/42 vs24/42，6个GPT5.5评判器各7例

**限制：** 不可用冻结评测证明自演化；窄任务只差1题；仪器Backend类型不等于实测闭环；迁移人时无受控证据

**先读：** §2.2、§3.2–3.3、附录10。

## 5. Data-driven acquisition offset correction for telescope networks using machine learning and sensitivity analysis

[原始来源](https://arxiv.org/abs/2610.34719)

首发：2026-10-26 · 版本：v1

机器人望远镜把目标坐标交给支架后，图像中实际位置仍可能偏离，原因包括机械形变、对准误差和随时间变化的仪器状态。传统指向模型需要校准和人工调整。这篇希望利用日常观测顺便留下的历史日志，学习下一次目标捕获时该修正多少，而不是再专门占用观测时间建立全部校准数据。

作者使用LCO南非Sutherland节点的数据，把观测时间、恒星时、要求指向的赤经赤纬与图像天体测量解算后的坐标对应起来。目标是预测要求坐标与解算坐标的差；由于两次捕获之间允许先算出上一次误差，也把上一条误差作为输入。模型主要采用XGBoost梯度提升树，并用神经网络和合成实验考察坐标变换、周期角度编码及系统偏差。上一条真实误差在这里是历史遥测中的可用特征，不是论文已经部署了实时自主科研代理。

真实日志实验按时间划分训练测试，比较原始偏差与离线预测修正后的残差。赤经方向平均绝对误差从0.354度降至0.0323度，赤纬从0.059度降至0.012度；它们分别约降至原来的十一分之一和五分之一，不能统一概括为两方向都降低十倍。表中还给出中位数及90分位数，表明改善不仅体现在一个平均值。基线是原始偏差，也没有提供在相同现场条件下胜过现役指向模型的完整对照。

部署部分让操作人员先整理固定列格式日志，提供台址经纬度与高度，再用脚本、Docker／Flask的训练预测API，或Streamlit的FLI-Point界面训练和查询。界面还支持“影子模式”：观测时只记录模型建议，望远镜继续使用原控制软件，之后再比较建议与实际误差。作者把现场影子测试、成功后进入控制回路都列为下一步，因此不能把软件可部署写成已完成实物闭环。

**作者证据：** 时间划分真实日志测试；RA平均绝对误差0.354→0.0323度约11倍、Dec0.059→0.012度约5倍；原始偏差为基线

**限制：** 14589条及70/10/20属坐标变换实验，非真实遥测分母；未现场对照现役模型；无资格费用/接入人时证据

**先读：** §4表3–4、§5–6。
