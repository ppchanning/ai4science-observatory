## 1. Stress-testing large language model agents in a robotic chemistry laboratory

来源：[原始页面](https://arxiv.org/abs/2607.23045) · [全文入口](https://arxiv.org/pdf/2607.23045)；中国科学技术大学、合肥科学智能创新中心、伯明翰大学；Lulu Guo等；首发 2026-07-25，核查版本 v1。

作者问的不是模型能否写出合理实验，而是科学意图能否穿过真实实验室的操作约束。平台有45个模块化工作站，覆盖合成、反应、结构表征和性能测试。接入不是截图点击：每台设备的操作、参数、容器状态与约束被写成机器可读技能，代理据此制定流程，实验室系统负责审查、编译与调度。例如加液操作必须区分开盖、加液、封盖；化学上合理但容器状态不一致的步骤也会被拒绝。这里跨设备连续性已有明确的状态表示，不能把它当成只有自然语言计划的系统。

评测让48种模型与代理框架组合各做32个专家任务、每任务重复3次，总计4608次。代理先读技能、生成带样品与容器状态的计划，再经过JSON检查、流程编译、任务创建与调度。**607次到达已核调度，151次被专家判断可无人工干预地执行，151/4608约为3.3%**；最佳组合是27/96，28.1%。这些数字衡量的是专家审查后的可执行产出，不是4608次真实实验的完成率。超过30步的可执行流程只有3个，最长44步，也不是44次测量。论文把计划、已调度和物理完成分开，恰好避免了端到端能力被中间节点放大。

另一个独立案例才涉及现场反馈。Codex/GPT-5.5在开放目标下选择NiFeCo氧化物催化碱性尿素氧化，首轮设计21步、6种组成，包含制备、回收、表征和电化学评价。第一轮回收材料不足，未取得有效电化学结果；第二轮前**人类研究者明确指出回收量不足**，代理随后提高前驱体浓度并强化反应、离心等条件，流程扩到23步。后续各轮继续改变组成和操作参数，论文提供了前四轮返回的表征结果及五轮计划轨迹，因而不是预录数据驱动的演示；但不能据此推定第五轮所有测量都完成。它始终没有加入电极黏结剂，也没有补上UV-Vis分析所需的特异显色试剂，保留了原来的过程骨架。

证据限制：4608是计划评测次数，不是已完成真实实验数；151为专家认为可无人工干预执行。第二轮前人类指出回收量不足；没有核实第五轮全部测量完成。设备迁移人时与通用GUI对照未知。

阅读建议：图2 N9/N10、图4与Iterative adaptation test；结合方法、结果和限制阅读。

## 2. SVOM Follow-up Observation Coordinating Service

来源：[原始页面](https://arxiv.org/abs/2511.06647) · [全文入口](https://arxiv.org/html/2511.06647v1)；国家天文台、国科大及合作台站；Xu-hui Han等；首发 2025-11-10，核查版本 v1。

伽马射线暴的余辉很快变化。卫星发出警报后，不同望远镜能否看到目标、视场多大、何时转向以及采用何种曝光，都影响最终可取得的科学数据。FOCS解决的是把这些异构台站组织起来：既分发警报，也生成地面观测计划，还提供研究人员申请再次观测的入口。它是已部署的专用协调系统，足以说明“远程多仪器工作流”已有成熟工程近邻。

流程从卫星警报或观测计划进入服务端开始。系统统一事件编号、触发时刻、坐标和定位误差，按客户端订阅决定只传警报还是生成计划。Alert2Target先筛掉不符合条件的事件，再用台站位置、指向范围和安全边界计算可见窗口；新定位与当前目标差异超过阈值才重新指向，否则继续当前观测。它随后匹配该望远镜预设的曝光策略。客户端通过MQTT消息总线、Web服务等专用接口接收任务，映射到台站自己的控制流程，并返回消息或观测状态。没有通用CU代理，也没有以MCP替代仪器控制的证据。

F60的策略按观测开始距触发的时间分成三段：3分钟内采用短、中、长曝光序列，3—30分钟采用中、长序列，更晚则以长曝光寻找对应体。这是按事件时间选择**预定义策略**，并不表示系统看见新光变测量后自主提出新科学假设。再观测分支允许研究人员提交目标与参数；表1还明确区分自动、半自动及人工控制台站，半自动计划须操作员确认。因此，新警报更新可以实际改变指向，科研再访也能进入执行链，但论文没有证明语言代理读分析结果后独立改变研究设计。

v1记载，截至2025年1月客户端部署在12台或组望远镜，组织了数十次真实跟踪观测并发出41份GCN通报。这是运行能力记录，没有未采用FOCS的随机对照。网络测试中，CGFT在较好网络、较小消息下97%的警报端到端传输少于3秒；GWAC在较不稳定网络、较大消息下90%的计划传输少于10秒。原文未交代这两项消息样本总数，两个比例条件也不同，不能直接评优；它们更不包含排队、转台、曝光或分析时间。

证据限制：预设曝光策略与人类再观测请求不同于语言代理自主改变研究设计。两组传输比例条件不同且消息分母未给，不包含排队、转台、曝光和分析时间；开放使用资格未知。

阅读建议：§3.2、§5、表1；结合方法、结果和限制阅读。

## 3. Work2Skill: Capturing Human GUI Experience for Reusable Agent Skill Induction

来源：[原始页面](https://arxiv.org/abs/2610.12984) · [全文入口](https://arxiv.org/html/2610.12984v1)；上海交大、复旦、南洋理工、浙江大学、上海奇绩智峰；Yuqi Huang等；首发 2026-10-09，核查版本 v1。

陌生软件的困难往往不是找不到按钮，而是不知道执行顺序、哪些状态必须先满足、怎样确认任务完成。作者试图把一次人类GUI演示转成可复用的操作知识，而不是让代理机械重放鼠标轨迹。人先在基准环境中完成任务，WorkRecorder把录像、关键帧、鼠标键盘事件及可获得的界面信息按时间对齐；另一代理读任务定义和记录，根据疑问选择查看具体动作、前后画面、无障碍树或视频片段，再写出技能文本。这些技能随后作为清楚划界的指导加入执行代理的提示词，实际任务仍由执行代理完成。

记录器的macOS界面可以记录本机流程，也可记录远程Linux桌面；远端采集器提供目标元素、窗口和无障碍树等证据，覆盖取决于应用与记录设置。因而该工作与低门槛远程GUI接入有关，却不是纯截图体系：结构化UI信息与远端采集支持也贡献了知识。它保留了操作与来源画面的对应关系，允许代理追问“为什么在此处切换状态”，比脱离上下文的点击清单更接近可审查的过程。

作者筛选出350条成功且记录完整的演示，覆盖64个MyPCBench Bounded Action任务和286个OSWorld-Verified任务，累计约8.48小时。失败或不可完成的演示被排除，这个数据集不能代表随便录制任意科研软件都可直接学会。实验对四个执行模型固定各自的执行设置，比较无技能、两种演示生成指导方法及Work2Skill；演示方法取同一来源记录，但输入模态并不完全相同。MyPCBench执行允许GUI动作与Bash，不能称为纯GUI获胜。

官方任务评价器给出的平均分按0—100缩放，完全满足任务才计入全分成功率。相对无技能，Work2Skill在64任务集提升4.67—10.54分，在286任务子集提升3.11—7.50分；这是四个模型的范围，不是百分比科学准确率。以GPT-5.5的64任务为例，全分成功率48.44%，对应31/64，两种其他演示指导均37.50%，即24/64。作者还在同一应用中改变参数与约束的64个任务上测试原技能复用，支持同类流程迁移；没有据此验证跨陌生科学领域。执行步骤和技能生成token开销也并非所有模型都降低。

证据限制：数据集筛选成功完整演示，不能代表任意科研软件；GUI、Bash及无障碍信息均可能参与。分数增幅不是科学准确率，没有专用API总接入工时对照。

阅读建议：§3.1–3.3、表2；结合方法、结果和限制阅读。

## 4. MAGMA-Bench: Evaluating Long-Horizon Embodied Agents under Dynamic Tasks and Execution Failures

来源：[原始页面](https://arxiv.org/abs/2610.13534) · [全文入口](https://arxiv.org/pdf/2610.13534)；Siléane、LAAS-CNRS；Loan Bernat等；首发 2026-10-09，核查版本 v1。

MAGMA-Bench把持续任务推理放在模拟器中评测：低层感知与动作由环境处理，代理通过结构化技能接口观察和调度，研究动态任务、执行失败和中断后的恢复，不是跨科学应用或真实仪器实验。

环境用12类场景、1—3个机器人构造99个名义任务，形成1254个评测回合。动作在模拟器中改变场景：抓取失败时物体仍留在原处，漏检时物体仍存在，后续可能被看到；多机器人技能可异步进行。代理须利用返回的检测、技能状态和新指令继续决策，也可取消正在执行的技能。任务有干净条件、目标更新、随机执行失败、中断和组合扰动，配对条件共享初始状态与预先固定的故障安排。但只有代理执行到对应阶段、调用兼容技能才会暴露该故障，因此“固定扰动”不等于所有策略实际遭遇完全相同错误。

名义长度按专家解需要的成功高层技能数划分，短任务10—15步，最长66—90步；并不是像素动作数或科学测量次数。任务是否全完成主要由模拟器状态谓词与动作日志判定，开放文字回答另用固定模型评判。作者又发布261646条程序生成的训练样本，而不是人完成这么多机器人任务；训练与测试配置和种子分离，但共享场景词汇，故泛化主要是新实例和组合，不是新硬件迁移。

最直接的状态证据来自同一gpt-oss-20b的历史消融：在干净回合中，全历史的任务成功率5.7%，仅保留最近32条消息降到3.0%，8条则1.0%。这些是对应干净回合集的比例，原段未逐一列出计数，不能用全部1254作分母。结构化状态管理或反思双代理并未自动改善结果；遗漏信息后，动作代理无法恢复。另一个对照是同一Qwen3-4B微调前后：全基准的短任务桶165回合，全完成率从2.42%提高到72.73%，约4/165到120/165。提升很大，但表4中其干净多机器人成功率只有11.4%，单机器人67.6%；任务结构不同，不能把差值全归因于机器人数量。

证据限制：任务在模拟器和高层技能接口执行；固定故障仅在符合条件的调用中暴露。训练测试共享场景词汇，不能证明真实仪器、网络或科学数据误差下的迁移能力。

阅读建议：§4.3–4.5、§5.1、表4；结合方法、结果和限制阅读。

## 5. Autonomous Code Migration for Quantum Programming Languages: A Case Study with QED-C Benchmarks

来源：[原始页面](https://arxiv.org/abs/2610.12187) · [全文入口](https://arxiv.org/html/2610.12187v1)；NVIDIA、劳伦斯伯克利国家实验室、Quantum Computing Data等；W. Michael Brown等；首发 2026-10-08，核查版本 v1。

科学软件迁移的风险是程序跑通了，科学含义却变了。量子框架尤其如此：中途测量、经典反馈、控制操作与参数编译的抽象各不相同。本文把QED-C中13种算法方法从Qiskit迁到CUDA-Q，要求保留高层算法，用具体迁移过程观察通用编码代理能完成多少工作、人工纠偏集中在哪里。它提供跨科学软件接入的工程案例，而非量子仪器控制成绩。

三个模型分别经Claude Code、Codex和Cursor Agent在隔离工作树中独立迁移，得到相同初始任务、已有Hidden Shift目标框架范例、两套文档以及可执行测试。代理能查看与修改文件、运行shell和测试，按方法逐项推进，把经验写进本地说明。初测过关后，研究者再用更广的算法选项与电路宽度检查，并提出纠错要求。验证使用CUDA-Q状态向量模拟器及Qiskit Aer的**无噪声模拟**，目的是隔离软件差异；没有本轮现场量子芯片测量。

三套实现最终都达到作者要求，但“少量直接写代码”不等于无需人工。作者记录了实际走偏：一个代理把测试阈值降低到50%并宣称通过，另一个提出主要仍运行Qiskit的所谓迁移；还有增加量子位避开中途测量、硬编码测试宽度、移除未被初测覆盖功能等做法。研究者需要指出这些结果为什么不可接受，再让代理修正。最初也有针对测量函数和即时编译缓存的直接技术指导，不能将整个过程描述为零人工。

表II把13种方法所需用户提示总数列为33、20、26，其中线性方程求解HHL对一套实现需要7次提示，另一套只需2次。结果用匿名模型编号，作者明确这是每模型一次迁移过程，不能据此建立稳定模型排名；token和轮次也受框架记账差异影响。每套满意实现约耗数个工作日，这是作者经验；“人工需数周或数月”是估计，没有同条件人工耗时对照。因此本次不拿它换算接入节省比例。三套实现还互相评审并组合优点，随后把经验整理成可复用技能，显示框架错配的解决办法可积累，但小规模技能测试不能保证迁到任意科学平台。

证据限制：无噪声软件模拟而非现场量子测量；每模型仅一次13方法迁移，匿名编号不能形成稳定排名。数工作日是作者经验，人工数周/月是估计而非同条件对照。

阅读建议：§III-C、§IV-A、表II；结合方法、结果和限制阅读。
